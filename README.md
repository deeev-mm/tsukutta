# 家庭料理ログ

**気になるレシピの出典を残し、うちの版として保存・アレンジする。作ったら家族でレビューする。**

ベースはリンク保存集 + 家族レビュー。  
調理者向けに、レシピ本文・サムネ・メモの保存と編集も持たせる Web アプリです。  
ユーザーは **家族単位** で増え、親ユーザー（Owner）は最初から調理者としても使えます。

詳細仕様（正） [docs/SPEC.md](./docs/SPEC.md)（v0.7.0）  
提案書 [docs/PROPOSAL_FOR_NON_ENGINEERS.md](./docs/PROPOSAL_FOR_NON_ENGINEERS.md)

---

## 何を解決するか

| よくあるやり方               | このアプリ                                                  |
| ---------------------------- | ----------------------------------------------------------- |
| ブラウザのお気に入りだけ     | **出典URL + うちの版レシピ**がセット                        |
| サイトを見ながら毎回思い出す | コピペ → **AI整形** → 保存し、**自分アレンジで編集**        |
| 人数が合わない               | **家族人数を設定**し、分量を自動換算                        |
| サイト画像をそのまま使う     | **サムネイル1枚**を任意でアップロード（ホットリンクしない） |
| アレンジが消える             | レシピの定番メモ ＋ **作った回の調理者メモ**                |
| 作った感想が散らばる         | **家族ごとの★・コメント**で残す（Phase 2）                  |
| どれが定番か曖昧             | 一覧 / カレンダー / ランキング / 殿堂入り                   |

---

## 入力の考え方

スクレイピングはしません。

1. **出典URL**を貼る（任意・参照用）
2. レシピ本文を **コピペ**
3. **Groq が構造化**（材料・手順など）→ プレビューで微修正 → 保存
   - 整形失敗時は **エラー**（手入力だけで新規保存する導線は置かない）
   - 既存レシピの編集は AI なしで可
   - **学習されてもよい内容だけ**送ること（画面に注意表記）
4. サムネイルは **任意・最大1枚**
5. 保存後はいつでも編集（うちの味にアレンジ）

## アカウント（家族単位）

```
親ユーザー登録（ID + パスワード・メール認証なし）
        ↓
家族（Family）作成 ※親 = Owner = 調理もできる
        ↓
Phase 1: 親がログインしてレシピ・記録を使う
        ↓
Phase 2: 親が家族アカウントを発行（追加 Cook / Reviewer）
```

| ロール                  | できること                                                                         |
| ----------------------- | ---------------------------------------------------------------------------------- |
| **システム管理者**      | ダッシュボード・Family停止・ユーザー横断・監査ログ・ヘルス（レシピ中身は触らない） |
| **親ユーザー（Owner＝調理者）** | 家族作成・調理全般・家族人数。**Phase 2** で追加アカウント発行。自分用に別 Cook は作らない |
| **追加の調理者（Cook）** | Phase 2 オプション。Owner 以外に調理させたいとき |
| **家族レビュー**        | 閲覧 + ★・コメント（Phase 2。編集しない）                                          |

認証は Phase 1 から必須（未ログインでは業務画面に入れない）。  
簡易な **ID + パスワード**。パスキーは後続で可。

### デモ Family

シードでデモ家族を用意しています。  
デモでも **レシピ新規作成（AI）まで操作可**（Groq キーは設定画面で localStorage に保存）。  
ログイン情報は下の「デモログイン」を参照。

## 主な機能

### Phase 1（MVP）— 認証 + レシピ + 記録

- 親登録・ログイン（**Owner＝調理者**。1アカウント）
- コピペ → AI整形 → 保存（1人前正規化）／既存編集は AI 不要
- 定番メモ（レシピ）／作った回の調理者メモ（ログ）
- サムネ任意・1枚
- 家族人数 → 分量換算（人前 input）
- 「作った」記録 / タイムライン・カレンダー・名前検索
- デモ Family シード

### Phase 2 — 家族レビュー + Admin

- 家族アカウント発行
- 家族レビュー（★・コメント）
- **料理カテゴリマスタ**（Owner/Cook が設定から CRUD、レシピ付与・一覧絞り込み）
- Admin（KPI・停止・監査・ヘルス・カテゴリ管理）

### Phase 3 — 見返し

- **ランキング**（全体 / カテゴリ別: 作った回数 → 平均★）
- **殿堂入り**（レシピ詳細から Owner/Cook が認定）
- **また作る**おすすめ（ホーム・見返し画面）

## 技術スタック

```
Next.js (UI) … 日本語のみ / モバイル優先
    │  Groqキー = localStorage（デモも同じ）
    ▼
Hono on Cloudflare Workers
    ├── D1 (SQLite 互換) … Family / User / Recipe / CookLog / …
    └── R2 … レシピサムネイル
```

| 層       | 技術                                    |
| -------- | --------------------------------------- |
| Frontend | Next.js（App Router）                   |
| Backend  | Hono × Cloudflare Workers               |
| Database | Cloudflare D1                           |
| ORM      | Drizzle                                 |
| Images   | Cloudflare R2（レシピサムネのみ・任意） |
| AI       | Groq（Llama 等・無料枠）                |
| Deploy   | Cloudflare Pages + Workers              |

### 設計のポイント

- **家族テナント** … データは Family 単位で分離
- **認証あり** … Phase 1 から。**Owner＝最初の調理者**（1アカウントで完結）。追加 Cook は Phase 2 のオプション
- **うちの版として持つ** … 出典は残しつつ、中身は編集可能な自分コピー
- **DBは1人前** … 画面の人前 input で掛け算表示
- **スクレイピングしない** … 規約・メンテ・ブロックのリスクを避ける
- **AIは登録の本線** … 失敗はエラー。既存編集は AI 不要
- **キー** … Groq APIキーは端末の localStorage（デモ Family も同じ。サーバー非永続）
- **CORSを前提にデプロイ** … Pages と Workers が別オリジンになりやすい。許可 Origin・API URL は環境変数で管理
- **エッジで軽く** … 無料枠・低レイテンシ優先

## デプロイ時の注意（CORS / 環境変数）

UI（Pages）と API（Workers）を分けると、ブラウザで **CORS エラー** が出やすいです。

| 変数（例） | どこ | 用途 |
|---|---|---|
| `NEXT_PUBLIC_API_BASE_URL` | Pages | フロントが叩く API の URL |
| `CORS_ALLOWED_ORIGINS` | Workers | 許可する UI Origin（例: Pages URL と `http://localhost:3000`） |
| `APP_BASE_URL` | 適宜 | Cookie / リダイレクト用の本体 URL |

実装時の要点:

- Workers で `Access-Control-Allow-Origin` 等を返す（Cookie 利用時は `*` 不可）
- `OPTIONS` プリフライトも許可する
- ローカルと本番の Origin を許可リストに入れる
- 可能なら同一ドメイン配下に API を載せて CORS 自体を減らす（詳細は SPEC §9.1）

## ローカル起動

Node.js 20+ / pnpm 推奨。

```bash
pnpm install

# D1 マイグレーション + デモ Family シード
pnpm setup:local

# API (http://localhost:8787) と Web (http://localhost:3000) を同時起動
pnpm dev
```

ログイン後の「設定」で Groq APIキーを端末の localStorage に保存してください（デモ `demo` も同じ）。  
キー発行: https://console.groq.com/keys

## ライセンス

プライベート / ポートフォリオ用途。  
外部レシピサイトのコンテンツの再配布・自動収集は行いません。

AI整形利用時は入力内容が Groq API に送信されます。学習等に使われる可能性があるため、学習されてもよい内容だけを入力してください。  
APIキーは各端末の localStorage にのみ保存します（デモ Family も同じ）。サーバーには永続保存しません。
