# tsukutta

**気になるレシピの出典を残し、うちの版として保存・アレンジする。作ったら家族でレビューする。**

「リンク保存集 + 家族レビュー」をベースに、調理者向けにレシピ本文・サムネ・メモの保存と編集を厚くした Web アプリです。  
公開レシピ百科でも横断スクレイパーでもなく、家庭内で完結する「うちのレシピ帳 + 作った記録 + 家族の声」を目指しています。

個人開発のポートフォリオ用途として、機能実装だけでなく **認証・マルチテナント・セキュリティ対策・運用画面までを一通り自分で設計・実装**しています。

詳細仕様（正） [docs/SPEC.md](./docs/SPEC.md)（v0.8.5）

## 主な機能

### レシピ管理
- コピペ → AI整形（Groq）→ プレビューで微修正 → 保存（材料は1人前に正規化）
- 材料は「材料名」「分量」を分けた構造化データで管理し、行単位で追加・削除・並び替え編集ができる
- 家族人数に応じた分量の自動換算（人前 input を変えると即座に再計算）
- サムネイル任意アップロード（EXIF等のメタデータは自動除去）
- 料理カテゴリでの分類・絞り込み、料理名・材料・メモ・タグを横断した検索

### 記録・見返し
- 「作った」記録（日付・一言メモ）、タイムライン・カレンダー表示
- ランキング（全体 / カテゴリ別）、殿堂入り、「また作る」おすすめ（作った回数・評価・直近性から算出）

### 家族のコミュニケーション
- 家族ごとの★・コメントレビュー
- 「今日のご飯何がいい?」— 調理者が候補を出し、家族が投票、調理者が決定するミニ意思決定フロー
- 決定した献立はホームに表示され、そこから買い物リストへの一括追加・「作った」記録へ直結
- 家族共有の買い物リスト（チェック管理・レシピからの一括追加）

### AI活用（コスト意識つき）
- AI整形は登録の本線（失敗時は手入力フォールバックせずエラー表示。中途半端な未構造化データを残さない）
- 「AIにおすすめを聞く」はボタンを押したときだけ呼び出す設計。ルールベースで候補を8件まで絞ってから渡すことで、無料枠のトークン消費を抑えている

### 運用（Admin）
- ダッシュボード（KPI集計）、テナント（Family）停止・再開、ユーザー横断管理、監査ログ、ヘルスチェック
- 家庭利用単体では不要な機能だが、マルチテナントSaaSの運用画面を一通り実装している

### PWA
- ホーム画面への追加に対応。Service Workerでアプリシェルをキャッシュし、オフライン時はフォールバック画面を表示（API通信はキャッシュ対象外）

## 技術的なこだわり

機能を揃えるだけでなく、実務でも問われる観点を意識して実装しています。

| 観点 | やったこと |
|---|---|
| マルチテナント境界 | 全APIで `familyId` によるスコープを徹底。他家族のデータへのIDORがないことを実装レベルで担保 |
| 認証 | PBKDF2（10万回）＋定数時間比較でパスワードハッシュ。セッションは生トークンを保存せずハッシュのみDBに保持 |
| CSRF対策 | Pages/Workers構成でセッションCookieが `SameSite=None` になる制約下、更新系メソッドは許可Origin以外を実処理前に403で拒否 |
| ブルートフォース対策 | ログイン失敗を記録し、5回失敗で一定時間ロックアウト（成功時はリセット） |
| 画像プライバシー | アップロード時にJPEG/PNGのメタデータ（EXIF等の位置情報を含みうる）をバイナリレベルで自前除去 |
| AIコスト設計 | 構造化・おすすめとも「必要なときだけ」呼ぶ設計。おすすめは候補をルールベースで事前に絞り込み、送信トークンを削減 |
| データモデリング | 材料を自由文字列ではなく `{name, amount, isSection}` の構造化データにし、分量換算を正規表現の名前/分量推測に依存しない形に設計し直した |
| 型安全なモノレポ | pnpm workspace + 共有パッケージ（`@tsukutta/shared`）でAPI/フロント間の型を共有。Drizzle ORMでスキーマとクエリを型安全に |
| エッジ構成 | Cloudflare Workers + D1 + R2 でサーバーレス運用。無料枠内・低レイテンシを意識 |

## 技術スタック

```
Next.js (UI) … 日本語のみ / モバイル優先
    │  Groqキー = localStorage（デモも同じ）
    ▼
Hono on Cloudflare Workers
    ├── D1 (SQLite 互換) … Family / User / Recipe / CookLog / MealProposal / …
    └── R2 … レシピサムネイル
```

| 層       | 技術                                    |
| -------- | --------------------------------------- |
| Frontend | Next.js（App Router） |
| Backend  | Hono × Cloudflare Workers               |
| Database | Cloudflare D1（SQLite 互換） |
| ORM      | Drizzle                                 |
| Images   | Cloudflare R2（レシピサムネのみ・任意） |
| AI       | Groq（Llama系・無料枠） |
| Deploy   | Cloudflare Pages + Workers              |

## ドメイン / DB

```
Family
  ├─ User（Owner＝調理 / 追加Cook / Reviewer）
  ├─ Recipe（notes: 定番メモ, image: サムネ任意）
  │     └─ CookLog（cookNote: その回の一言）
  │           └─ Rating
  ├─ MealProposal（今日のご飯提案）
  │     └─ Candidate ── Vote
  └─ ShoppingListItem（家族共有の買い物リスト）
```

D1 のテーブル定義・ER・INDEX・DDLは [docs/SPEC.md](./docs/SPEC.md) の「4.6 DB設計」を参照。

## ローカル起動

Node.js 20+ / pnpm 推奨。

```bash
pnpm install

# D1 マイグレーション + デモ Family シード
pnpm setup:local

# API (http://localhost:8787) と Web (http://localhost:3000) を同時起動
pnpm dev
```

ログイン後の「設定」で Groq APIキーを端末の localStorage に保存してください（デモ `demo` も同じ）。  
キー発行: https://console.groq.com/keys

## デプロイ時の注意（CORS / 環境変数）

UI（Pages）と API（Workers）を分けると、ブラウザで **CORS エラー** が出やすいです。

| 変数（例） | どこ | 用途 |
|---|---|---|
| `NEXT_PUBLIC_API_BASE_URL` | Pages | フロントが叩く API の URL |
| `CORS_ALLOWED_ORIGINS` | Workers | 許可する UI Origin（例: Pages URL と `http://localhost:3000`） |
| `APP_BASE_URL` | 適宜 | Cookie / リダイレクト用の本体 URL |

詳細は [docs/SPEC.md](./docs/SPEC.md) の「9.1 デプロイ・CORS・環境変数」を参照。

## ライセンス

プライベート / ポートフォリオ用途。  
外部レシピサイトのコンテンツの再配布・自動収集は行いません。

AI整形・AIおすすめ利用時は入力内容が Groq API に送信されます。学習等に使われる可能性があるため、学習されてもよい内容だけを入力してください。  
APIキーは各端末の localStorage にのみ保存します（デモ Family も同じ）。サーバーには永続保存しません。
